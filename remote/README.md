# SSH 원격 파일을 세토로 편집하기

`seto test.md`는 **원격 서버에서 실행하는 Python 도우미**입니다. 세토 iPhone·iPad 앱은
현재 SSH 연결에 두 번째 실행 채널을 열고, 도우미가 전달한 파일을 기존 네이티브
`HardwareTextEditor`로 편집합니다. 별도 네트워크 서버·포트·로그인 토큰이 필요하지 않습니다.
원격 도우미를 앱이 자동으로 설치하거나 기존 원격 파일을 임의로 변경하지 않습니다.

## 설치 (사용자가 검토한 뒤 직접 실행)

Unix 계열 OpenSSH 서버와 Python 3.8 이상이 필요합니다. 다음 명령의 `user@host`를 실제
서버로 바꾸세요. 저장소의 `remote/seto` 소스를 먼저 검토하고, 서버에 기존 `seto`가 있으면
덮어쓰기 전에 별도로 백업하세요. 다른 SSH 포트를 쓰면 ssh의 `-p`, scp의 `-P`도 지정합니다.

```sh
# 로컬 컴퓨터의 이 저장소에서 실행. 아래 명령은 실제 원격 서버에 파일을 설치합니다.
ssh user@host 'mkdir -p "$HOME/.local/bin"'
scp remote/seto user@host:.local/bin/seto
ssh user@host 'chmod 700 "$HOME/.local/bin/seto"; python3 --version'
```

서버의 셸 시작 파일에 아래 PATH 설정을 추가하거나, 접속할 때마다 직접 실행하세요.
앱의 실행 채널은 PATH와 관계없이 `~/.local/bin/seto`를 사용합니다.

```sh
export PATH="$HOME/.local/bin:$PATH"
```

## 사용

1. 앱의 **SSH 터미널**에서 서버에 접속하고 서버 키 지문을 확인합니다.
2. 문서 아이콘 메뉴에서 **파일 편집 연결**을 누릅니다. 가로 화면에서는 아래쪽에 있습니다.
   메뉴에 ‘편집 연결됨’이 표시되는지 확인합니다. 접속할 때마다 한 번 연결합니다.
3. 터미널에서 실행합니다.

   ```sh
   cd ~/project
   seto test.md
   # 공백·한글 이름, 파일명으로 시작하는 옵션 구분도 지원
   seto '새 문서.md'
   seto -- '--bridge'
   ```

4. 앱의 네이티브 편집창에서 세벌식 390 등 선택한 하드웨어 자판으로 편집합니다.
   **저장** 또는 **⌘S**를 눌러 ‘서버 저장 완료’를 확인합니다. 자동 원격 저장은 없습니다.
5. **닫기**를 누르면 기존 터미널로 돌아옵니다. 미저장 내용이 있으면 계속 편집하거나
   ‘초안을 기기에 보관하고 닫기’를 선택합니다. 다른 파일을 열려면 먼저 편집기를 닫습니다.

파일이 없으면 빈 문서로 열리며 **처음 저장할 때 생성**됩니다. 닫기만 하면 서버에 만들지
않습니다. 상위 폴더는 먼저 만들어야 합니다. 빈 새 파일도 저장 버튼으로 생성할 수 있습니다.
최대 1 MiB의 UTF-8 텍스트 하나를 지원합니다. NUL 문자가 있는 파일은 거부합니다.
원래 바이트의 줄바꿈·마지막 줄바꿈을 도우미가 임의로 바꾸지 않습니다.

## 초안 복구와 충돌

앱은 변경 시 서버 주소·포트·사용자·절대 경로별 초안을 로컬에 보관합니다. 미저장 내용은
닫기·연결 단절·백그라운드 전환 뒤에도 유지됩니다. 연결 화면과 문서 메뉴의 **초안**으로
내용을 다시 열어 복사할 수 있습니다. 앱 데이터 삭제·앱 제거 시에는 초안도 삭제됩니다.

재접속 뒤 같은 경로를 `seto`로 다시 열면 초안을 복구합니다. 서버 버전이 달라졌으면
저장을 차단하고 초안 복사를 안내합니다. 초안을 복사한 뒤 **닫기 → 초안 버리고 닫기**를
선택하고 `seto`로 다시 열면 최신 서버 파일을 읽습니다. 버린 초안은 앱에서 복구할 수 없습니다. 자동 병합·강제 덮어쓰기는 제공하지 않습니다. ACK가 유실됐더라도
다시 읽은 서버 내용과 초안이 같으면 저장된 내용으로 확인하고 복구 사본을 정리합니다.
ACK 대기 중 계속 입력한 부분은 다음 저장 때까지 초안으로 남습니다.

저장 응답이 늦거나 연결이 끊기면 저장 여부를 추측하지 않습니다. 초안을 보관하고 파일을
다시 열어 서버 상태를 확인합니다. 연결 종료 후 재접속하면 같은 명령을 자동 재생하지 않습니다.

## 파일 저장 의미와 제한

- 일반 파일만 편집합니다. 파일 자체가 심볼릭 링크·하드 링크·폴더·장치·FIFO인 경우 거부합니다.
  심볼릭 링크를 가리키는 상위 폴더는 열 때 실제 경로로 고정합니다. 상위 폴더가 교체되면 저장을 거부합니다.
- 현재 사용자 소유의 파일만 지원합니다. 읽기 전용·특수 권한 비트가 있는 파일은 저장하지 않습니다.
  새 파일 권한은 원격 실행 채널의 umask를 따릅니다.
- 기존 파일은 같은 폴더의 임시 파일에 쓰고 `fsync`한 뒤 원자적 rename으로 교체합니다.
  UID/GID·권한·지원되는 확장 속성/ACL을 보존하며, 메타데이터 복사에 실패하면 교체하지 않습니다.
  inode·수정/변경 시각은 바뀝니다. 생성 시각 등 파일시스템별 메타데이터는 모두 보존하지 않습니다.
  심볼릭 링크·하드 링크·다른 소유자 파일을 거부하는 것은 이 교체 의미 때문입니다.
- 버전에는 내용 해시와 inode·장치·크기·mtime·ctime·소유자·권한·링크 수를 포함합니다.
  내용을 쓰기 전과 교체 직전에 다시 검사합니다. 삭제·동일 내용으로의 파일 교체도 충돌입니다.
  여러 세토 도우미의 저장은 폴더의 advisory lock으로 직렬화합니다.
- **새 파일 생성은 atomic create-if-absent**입니다. 검사 직후 다른 프로그램이 같은 이름을
  만들더라도 절대 덮어쓰지 않습니다.
- **기존 파일에는 POSIX의 범용 원자적 compare-and-swap이 없습니다.** advisory lock을 따르지 않는
  외부 프로그램이 최종 검사와 rename 사이의 짧은 구간에 수정하면 완전한 충돌 방지를 보장할 수 없습니다.
  저장 직후에도 다시 읽어 확인하지만 이 경쟁 구간을 없애지는 못합니다. 동시 작성은 피하세요.
  NFS 등 원격 파일시스템의 잠금·rename·fsync 의미도 별도 확인이 필요합니다.
- 서버 ACK는 파일과 상위 폴더 fsync 및 저장 내용 확인 뒤에만 보냅니다.
  rename 후 ACK 이전에 단절·디스크 오류가 나면 이미 저장되었을 수 있어 재열기로 확인합니다.

## 연결과 프로토콜

고정된 NIOSSH 버전의 `createChannel(.session)`과 `ExecRequest`를 사용합니다.
NIOSSH가 SFTP 클라이언트를 제공한다고 가정하지 않습니다. 기존 PTY 셸은 그대로 두고,
명시적으로 연결한 비 PTY 실행 채널에서 아래 고정 명령만 실행합니다.

```sh
exec python3 "$HOME/.local/bin/seto" --bridge
```

경로·파일 내용은 셸 명령에 삽입하지 않으며 JSON 줄 프레임으로만 교환합니다.
프로토콜 버전·연결별 무작위 128비트 세션 ID·저장 요청 ID·파일 경로를 앱에서 검증합니다.
입력 프레임 크기도 제한합니다. 표준 오류·일반 터미널 출력·OSC·키 입력은 편집 요청으로 파싱하지 않습니다.

도우미는 OpenSSH가 각 채널에 제공하는 `SSH_CONNECTION`의 해시로 같은 SSH transport를
식별합니다. `/tmp/seto-UID`(0700, 소유자 확인)에 연결 레코드(0600)와 무작위 이름의 Unix
소켓을 두고, 동일 사용자로 실행한 `seto`가 자기 연결의 세션 ID를 읽어 요청합니다.
앱이 연 실행 채널의 도우미가 소켓 요청을 파일 읽기 응답으로 바꿉니다. 채널 종료/EOF 때
소켓·레코드를 정리합니다. 비정상 강제 종료의 잔여 레코드로 다른 연결에 붙지는 않습니다.
이 도우미는 SSH 실행 채널 수명 동안만 실행되며 상시 서비스로 설치하지 않습니다.

원격 계정의 다른 프로그램은 같은 사용자 권한으로 이 소켓과 파일에 접근할 수 있습니다.
SSH 계정 자체가 신뢰 경계이며 동일 계정의 악성 프로세스로부터 격리하지 않습니다.
도우미 파일·홈 폴더도 그 계정에서 신뢰할 수 있어야 합니다.

서버는 최소 두 SSH session 채널과 원격 exec를 허용해야 합니다 (`MaxSessions`, forced command
등 확인). OpenSSH 외의 서버는 두 채널에 같은 `SSH_CONNECTION`을 제공하는지 확인해야 합니다.
첫 버전은 로그인한 셸에서 직접 사용하세요. 오래된 tmux/screen 창, `sudo`로 바꾼 사용자,
중첩 SSH는 환경/계정이 달라 연결을 찾지 못할 수 있습니다. `seto --wait` 및 Git EDITOR는 미지원입니다.

## 검증

```sh
python3 -m unittest discover -s remote/tests -v
# iOS 빌드와 UIKit 테스트는 iOS/README.md 참고
```

도우미 테스트는 실제 임시 파일·Unix 소켓·별도 프로세스로 상대 경로/한글/공백, 새 파일 경쟁,
원격 변경/삭제/교체, 권한·링크·바이너리 거부, 디스크 오류, ACK, 잘못된 세션, 단절 정리를 검증합니다.
`SSHRemoteEditorTests`와 `SSHRemoteFramingTests`는 세션 검증, 프레임 분할/크기 제한, 세벌식
입력 저장, ACK 순서와 저장 중 추가 입력, 단절/재접속 초안, 충돌과 ACK 유실 복구를 검증합니다.

추가로 실기기/실제 SSH 서버에서 확인할 항목:

- iPhone·iPad 가로/세로 및 외부 키보드에서 ⌘S, 한영 전환, 조합 중 저장과 닫기 후 터미널 포커스.
- 서버 설치·PATH, 서버 키 검증, 실제 `SSH_CONNECTION` 전달과 두 번째 채널 허용.
- 편집 중 네트워크 차단·백그라운드·앱 재실행, ACK 직전 단절과 같은 서버 재접속 복구.
- 서로 다른 서버/사용자/동시 SSH 접속의 요청 격리, 기존 tmux 환경의 제한.
- 대상 서버의 파일 권한·ACL·xattr·umask 및 파일시스템별 내구성/동시 외부 작성 의미.
