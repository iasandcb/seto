# 세토 iPhone 앱

iOS 16 이상을 위한 SwiftUI 안내·연습 앱과 UIKit 키보드 확장입니다.
`Sources/Sebeol390Core`를 macOS 입력기와 공유합니다. 외부 패키지는 없습니다.

## 실행

1. Xcode에서 `iOS/Sebeol390.xcodeproj`를 엽니다.
2. `Sebeol390` 스킴과 아이폰 또는 시뮬레이터를 선택합니다.
3. 실기기는 앱과 `Sebeol390Keyboard` 타깃의 Signing & Capabilities에서 본인의 Team을 선택합니다. 필요하면 두 Bundle Identifier를 고유한 값으로 바꾸되 확장의 식별자는 앱 식별자 아래에 둡니다.
4. Run으로 설치합니다.
5. 아이폰 설정 → 일반 → 키보드 → 키보드 → 새로운 키보드 추가 → 세토를 선택합니다.
6. 앱의 연습장을 누르고 지구본을 길게 눌러 세토를 선택합니다.

전체 접근 허용은 필요하지 않습니다. 확장에는 네트워크 접근이나 오타 기록을 넣지 않았습니다.
연습장 내용은 안내 앱의 UserDefaults에 저장되며 지우기로 삭제할 수 있습니다.
자동 전환 설정은 키보드 확장 자체의 UserDefaults에 저장합니다.

## 조작

연습장 제목 옆 **최대화**를 누르면 입력장이 화면 전체로 펼쳐집니다.
상단 **축소**로 안내 화면으로 돌아오며 입력 내용은 두 화면에서 공유됩니다.
일반 화면의 **내용 복사** 또는 최대화 화면 상단의 복사 아이콘으로 입력창 전체 내용을 복사합니다.
복사가 끝나면 잠시 체크 표시가 나타나며, 입력창이 비어 있으면 버튼은 비활성화됩니다.

- 4개 행은 QWERTY 물리 위치를 그대로 옮긴 세벌식 390입니다.
- ⇧: 다음 글쇠의 윗글자. 390 숫자도 여기 있습니다.
- 123: 일반 숫자·기호 자판으로 전환합니다. 다시 누르면 390으로 돌아옵니다.
- 한/영 ↶: 엔진의 언어 전환·직전 자동 변환 되돌리기입니다.
- 상단 상태 표시: 자동 한/영 전환 켜기·끄기입니다.
- 지구본: 다른 키보드로 이동하거나 키보드 목록을 엽니다.

암호·일부 전화번호 입력란과 외부 키보드를 허용하지 않는 앱에서는 시스템 키보드가 사용됩니다.
### 하드웨어 키보드

앱의 연습장을 누르면 Bluetooth·USB 키보드로 즉시 세벌식 390을 입력할 수 있습니다.
터치 키보드 확장을 활성화하지 않아도 앱 안의 하드웨어 입력은 동작합니다.

- 물리 QWERTY 위치 기준으로 입력하므로 시스템 자판의 문자 매핑에 의존하지 않습니다.
- Shift+Space로 현재 단어의 읽기를 바꾸거나 직전 자동 변환을 되돌립니다.
- Backspace는 조합 중 자모를 하나씩 지우고, 조합 밖에서는 일반 삭제를 합니다.
- 방향키·Enter·Tab·Esc와 Command/Control/Option 조합은 기본 편집기에 넘깁니다.
- 선택 영역 교체, 붙여넣기와 커서 이동 시 이전 입력 세션을 초기화합니다.
- Caps Lock은 시스템 설정과 충돌할 수 있어 전환 키로 가로채지 않습니다.

지원 범위는 **세토 앱의 연습장**입니다. iOS 공개 API에는 다른 앱의 하드웨어 키 이벤트를
키보드 확장에 전달하거나 시스템 하드웨어 입력기로 등록하는 기능이 없습니다.
앱의 하드웨어 입력은 자동 한/영 전환이 기본으로 켜지며 확장의 설정과 별도로 동작합니다.

## 검증

```sh
# Xcode가 활성 개발자 디렉터리가 아닌 경우 명령 앞에
# DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer 를 붙입니다.
xcodebuild -project iOS/Sebeol390.xcodeproj -scheme Sebeol390 \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath /tmp/sebeol390-ios-build CODE_SIGNING_ALLOWED=NO build
swift test
# 부팅된 시뮬레이터 이름 또는 ID를 지정하여 UIKit 통합 테스트를 실행합니다.
xcodebuild -project iOS/Sebeol390.xcodeproj -scheme Sebeol390 \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' \
  -derivedDataPath /tmp/sebeol390-ios-build CODE_SIGNING_ALLOWED=NO test
```

`HardwareKeymapTests`는 물리 키 매핑·Shift·단축키 통과·조합을 검증합니다.
`HardwareTextEditorTests`는 시뮬레이터의 실제 UITextView에서 조합·자모 삭제·언어 전환·이모지 보존·커서 이동·선택 영역 교체·붙여넣기 후 입력을 검증합니다.
`KeyboardReplacementTests`는 이모지·한글의 글자 단위 교체와 엔진 입력·삭제·전환 결과의 재생을 검증합니다.
iOS 확장에는 marked text API가 없어 조합 결과의 변경된 접미사만 삭제·삽입합니다.
커서·선택 영역·문서가 바뀌면 세션을 초기화하고, 삭제 직전 문맥이 맞는지 확인합니다.
문맥을 제공하지 않는 입력란에서는 기존 텍스트를 안전하게 교체할 수 없어 조합을 초기화합니다.

실기기에서 빠른 연속 입력, 커서 이동, 선택 후 입력, 앱 전환, 가로 화면과 VoiceOver를 확인해야 합니다.
App Store 배포용 아이콘·서명·심사 준비는 별도입니다.

## 프로젝트 재생성

프로젝트는 저장소에 포함되어 있으므로 바로 열 수 있습니다. 코어 파일을 추가한 경우:

```sh
python3 iOS/scripts/generate-project.py
```

수동으로 변경한 프로젝트 설정과 Info.plist는 재생성 시 덮어써집니다.
단어 목록과 해당 라이선스·NOTICE는 앱과 확장 번들에 함께 포함됩니다.

## mark-vector 연동

앱 첫 화면에서 **mark-vector 문서 열기**를 누릅니다. 기본 서버는
`https://markvector.fly.dev`이며 HTTPS 서버 주소를 바꿀 수 있습니다.

1. 앱 안의 웹 화면에서 mark-vector에 로그인합니다. 세션은 WebKit 저장소에 유지됩니다.
2. 프로젝트·폴더에서 문서를 선택합니다. 웹에서 편집했다면 먼저 웹의 저장 버튼을 누릅니다.
3. 상단 **세토로 편집**을 누르면 저장된 문서를 화면 전체의 네이티브 편집창으로 가져옵니다.
4. 하드웨어 키보드로 입력하면 WebSocket으로 서버에 자동 저장되고 맥의 같은 문서와 미리보기에 즉시 반영됩니다. **저장** 또는 **⌘S**는 현재 내용의 서버 저장 완료를 확인합니다.
   복사 아이콘으로 전체 내용을 복사할 수도 있습니다.

일반 프로젝트 문서를 지원합니다. 전역 시스템 프롬프트·공용 수식 문서 등은 웹에서 편집합니다.
문서 열기·HTTP 저장 요청은 로그인한 웹 페이지와 같은 출처에서 실행됩니다.
실시간 연결은 WebKit 저장소의 해당 서버 세션 쿠키를 메모리에서만 읽어 네이티브
URLSessionWebSocketTask에 전달합니다. 비밀번호나 별도의 API 토큰을 보관하지 않습니다.
키보드 확장은 서버에 접속하지 않습니다.

네이티브 편집 중 변경 내용은 서버·문서별로 앱의 UserDefaults에 복구용으로 보관합니다.
같은 문서를 다시 열면 복구하며, 서버의 저장 완료 ACK를 받은 최신 내용의 복구 사본을 지웁니다.
약 60ms 간격으로 최신 입력을 합쳐 보내며, ACK를 기다리는 동안 새 입력을 로컬에 유지합니다.
연결이 끊기면 입력은 계속할 수 있고 재연결 시 최신 스냅샷을 전송합니다. 상태는 편집창
아래에 표시합니다. 서버가 저장을 확인하기 전에는 ‘저장됨’으로 표시하지 않습니다.
앱이 백그라운드로 가면 연결을 닫고 복귀 시 다시 연결합니다.

아이폰 한 대를 편집 주체로 사용합니다. 여러 작성자의 변경 병합은 지원하지 않습니다.
맥에서는 같은 문서를 열어 두고 웹 탭을 한 번 새로고침하면 실시간 내용을 볼 수 있습니다.
맥에 미저장 수정이 있으면 먼저 저장하거나 해당 수정을 정리해야 실시간 구독이 반영됩니다.
실시간 스냅샷은 전용 인증 경로로만 전달하며 공개 라이브·안경 채널로 보내지 않습니다.

`MarkVectorIntegrationTests`는 실제 WKWebView의 모의 서버 응답으로 문서 열기·URL 인코딩·
저장·버전 충돌·웹 미저장 문서 보호를 검증합니다. 실제 서비스의 로그인과 저장은 사용자
아이폰에서 확인해야 합니다. 앱은 LLM 전송을 자동 실행하지 않습니다.

`MarkVectorLiveSyncTests`는 전송 대기 중 입력 병합, ACK 순서, 재연결 스냅샷과 저장 완료 판정을 검증합니다.
