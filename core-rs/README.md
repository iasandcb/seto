# seto-core (Rust)

Shared core of Seto. The Swift code in `Sources/SetoCore` is the oracle; this
crate ports it piece by piece.

Phase 1 (this crate today): `hangul`, `composer`, `layout` (390, 최종, 두벌식,
`KeyboardLayout`), `keys` (`keymap`, `hardware_keymap`, `KeyboardReplacement`,
`ShiftSpaceToggleTracker`), `lexicon`, and the `Session` value types
(`Language`, `FieldEdit`, `SessionUpdate`). `Session` and `TypoCorrector` are
not ported yet.

```sh
cd core-rs && cargo test
```

## Lexicon

Word lists are one sorted UTF-8 buffer plus a `u32` offset table; lookups
binary-search byte slices without allocating a `String` per word. The large
lists are memory-mapped from files already in the repository:

- `Lexicon::load(Resources/)`: English is expanded with plurals in memory,
  `korean-valid.txt` is mapped (its comment header is skipped).
- `Lexicon::load_for_keyboard*`: maps `iOS/Keyboard/Resources/keyboard-english.txt`
  and `keyboard-korean-valid.txt` (generated by `iOS/scripts/generate-project.py`).

## Golden corpus

`testdata/session-golden.json` records the real Swift `Session`, call by call,
for every Session-driving test in `SessionTests.swift`,
`TransitionCorpusTests.swift`, `DubeolTests.swift`, `KeyboardLayoutTests.swift`,
`KeyboardReplacementTests.swift` and `HardwareKeymapTests.swift`. The schema is
`seto_core::golden`; every `FieldEdit` span is in UTF-16 code units.

Regenerate it from the repository root (the dump target is only part of the
package when the variable is set, so a plain `swift test` never rewrites it):

```sh
SETO_GOLDEN_DUMP=1 swift test --filter SetoGoldenDump
```

The three dictionary sweeps (`commonEnglishWordsDoNotFlipMidWord`,
`dictionaryWordsAreNotAutoCorrected`, `koreanWordsStayKoreanBeforeParticles`)
are sampled to about 500 sessions each by content hash; the file header lists
them. `SETO_GOLDEN_FULL=1` keeps every session (about 110 MB).
